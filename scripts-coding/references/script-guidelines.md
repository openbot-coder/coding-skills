# Script Coding Guidelines

## 1. 目录结构规范

### 1.1 脚本存放位置

脚本应根据使用期限存放在以下目录：

| 目录 | 用途 | 说明 |
|------|------|------|
| `scripts/` | 长期使用的脚本 | 稳定、可复用的脚本 |
| `tmp/` | 临时使用的脚本 | 一次性或短期使用的脚本 |
| `.trash/` | 废弃脚本 | 已完成任务的临时脚本存档 |

### 1.2 目录检查流程

```
用户请求创建脚本
    ↓
询问脚本类型（长期/临时）
    ↓
检查目标目录是否存在
    ↓
├── 存在 → 使用该目录
└── 不存在 → 询问用户是否创建
    ↓
├── 是 → 创建目录并使用
└── 否 → 询问用户指定其他位置
```

## 2. 文件命名规范

### 2.1 命名格式

```
{创建日期}-{代码用途}-{标志}-{版本}.py
```

### 2.2 各部分说明

| 部分 | 格式 | 示例 | 说明 |
|------|------|------|------|
| 创建日期 | YYYYMMDD | 20260509 | 脚本创建的日期 |
| 代码用途 | 小写字母，连字符分隔 | data-processor | 简短描述脚本功能 |
| 标志 | long \| temp | long | long=长期脚本，temp=临时脚本 |
| 版本 | v1, v2... | v1 | 可选，用于版本管理 |

### 2.3 命名示例

```
# 长期脚本
20260509-data-processor-long-v1.py
20260509-api-client-long.py

# 临时脚本
20260509-quick-test-temp.py
20260509-data-analysis-temp-v2.py
```

## 3. 文件头部注释规范

### 3.1 必须包含的内容

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
================================================================================
@Author:         [作者姓名]
@Created:        [创建日期 YYYY-MM-DD]
@Last Modified:  [最后修改日期 YYYY-MM-DD]

================================================================================
## Purpose (创建目的)
[描述创建本文件的目的]

## Background (背景)
[描述创建本文件的背景信息]

## Scope (使用范围)
[描述本脚本的使用范围和适用场景]

## Usage (使用规范)
[描述如何使用本脚本]

## Features (实现功能)
[列出本脚本实现的主要功能]

================================================================================
"""
```

### 3.2 注释编写要求

- 作者：填写脚本编写者姓名
- 创建日期：使用 YYYY-MM-DD 格式
- 最后修改日期：每次修改后更新
- 创建目的：简明扼要说明脚本用途
- 背景：说明创建脚本的原因和上下文
- 使用范围：明确脚本适用的场景
- 使用规范：提供使用方法和示例
- 实现功能：列出脚本的核心功能

## 4. 日志管理规范

### 4.1 日志存放位置

```
项目根目录/
└── .trash/
    └── logs/
        ├── script1.log
        └── script2.log
```

### 4.2 日志文件名格式

```
{脚本文件名}.log
```

### 4.3 日志记录内容

| 内容 | 说明 | 示例 |
|------|------|------|
| 脚本启动 | 记录脚本开始执行时间 | `2026-05-09 10:00:00 - INFO - Script started` |
| 命令参数 | 记录传入的命令行参数 | `Command line arguments: ['-i', 'input.txt']` |
| 执行步骤 | 记录关键执行步骤 | `Processing data...` |
| 执行结果 | 记录脚本执行结果 | `Script completed successfully` |
| 错误信息 | 记录错误和异常 | `Error occurred: FileNotFoundError` |

### 4.4 日志格式

```
YYYY-MM-DD HH:MM:SS - LEVEL - Message
```

## 5. 脚本开发规范

### 5.1 语言选择

- **优先使用 Python**：除非用户明确指定其他编程语言
- 版本要求：Python 3.8+
- 编码格式：UTF-8

### 5.2 代码风格

- 遵循 PEP 8 规范
- 使用 4 空格缩进
- 行长度不超过 88 字符
- 使用清晰的变量和函数命名

### 5.3 错误处理

- 使用 try-except 块处理异常
- 记录错误日志
- 提供有意义的错误信息
- 优雅地处理失败情况

### 5.4 参数处理

- 使用 argparse 处理命令行参数
- 提供默认值
- 添加参数说明
- 支持 --help 参数

## 6. 脚本生命周期

### 6.1 创建阶段

1. 使用模板创建脚本
2. 填写文件头部注释
3. 实现核心功能
4. 添加日志记录

### 6.2 使用阶段

1. 测试脚本功能
2. 记录执行日志
3. 根据需要更新脚本

### 6.3 归档阶段

1. 临时脚本完成任务后移至 `.trash/`
2. 长期脚本保持在 `scripts/`
3. 定期清理 `.trash/` 目录

## 7. 最佳实践

1. **保持简洁**：脚本应专注于单一任务
2. **文档齐全**：确保头部注释完整
3. **日志完整**：记录关键执行信息
4. **错误处理**：优雅处理异常情况
5. **版本控制**：使用 git 管理脚本变更
6. **定期清理**：及时清理不再需要的临时脚本
