# 安全审计 Skill

> 版本：1.0.0
> 适用场景：代码库安全漏洞扫描与风险评估

## 目标

识别中等严重度及以上的**已确认漏洞**，且必须具备可论证的端到端利用路径。

**不报告**：
- 理论性风险
- 推测性漏洞
- 缺少利用证据的问题

---

## 核心原则

### 1. 证据驱动
每个报告的问题必须包含：
- 攻击者画像
- 可控输入向量
- 从输入到漏洞的完整代码路径
- 可量化的影响
- 具体修复建议

### 2. 严重度分级

| 级别 | 定义 | 示例 |
|------|------|------|
| **严重（Critical）** | 远程代码执行、数据大规模泄露 | SQL 注入 RCE、未授权管理接口 |
| **高危（High）** | 权限提升、敏感数据泄露 | 越权访问、会话劫持 |
| **中危（Medium）** | 有限数据访问、服务降级 | XSS（存储型）、CSRF |

### 3. 审计范围

仅关注以下攻击面：

| 分类 | 检查项 |
|------|--------|
| **认证与访问控制** | 登录流程、会话管理、角色/权限校验 |
| **注入向量** | SQL 查询、Shell 命令、模板渲染、文件路径操作 |
| **外部交互** | Webhook、HTTP 请求、第三方 API |
| **敏感数据** | 密钥/凭证日志、PII 处理、加密实现 |

## 审计流程

### 阶段1：架构梳理

```
1. 识别入口点
   - API 路由
   - CLI 命令
   - WebSocket/GraphQL 端点
   - 定时任务/Cron

2. 定位信任边界
   - 认证中间件
   - 授权装饰器
   - API 网关配置

3. 追踪数据流
   - 用户输入 → 处理逻辑 → 存储/响应
   - 外部 API 回调路径
   - 配置加载流程
```

### 阶段2：攻击面检查

按优先级检查以下分组：

#### A. 认证与访问控制

| 检查点 | 危险信号 |
|--------|----------|
| 会话令牌生成 | 使用 `Math.random()`、时间戳作为种子 |
| 密码存储 | 明文/MD5/SHA1 哈希 |
| 权限校验 | 缺少中间件、校验逻辑错误 |
| MFA 实现 | 验证码可预测、重放攻击 |

#### B. 注入向量

| 类型 | 检测模式 |
|------|----------|
| SQL 注入 | 字符串拼接 SQL、ORM 误用 |
| 命令注入 | `exec()`、`eval()`、`shell_exec()` + 用户输入 |
| 模板注入 | 用户输入直接渲染模板 |
| 路径遍历 | 路径拼接未校验 `../` |

#### C. 外部交互

| 检查点 | 关注内容 |
|--------|----------|
| Webhook | 签名校验缺失、回调地址可控 |
| 出站请求 | SSRF、URL 重定向 |
| 第三方集成 | 凭证硬编码、回调处理 |

#### D. 敏感数据

| 检查点 | 危险模式 |
|--------|----------|
| 密钥管理 | Git 历史、配置文件、环境变量 |
| 日志泄露 | 密码、Token、PII 写入日志 |
| 加密实现 | 自定义算法、可预测 IV |

### 阶段3：利用路径验证

对于每个潜在发现，必须追踪：

```
攻击者输入 → 传播路径 → 触发点 → 影响结果
```

**示例追踪链**：

```
用户请求参数 → URL 路由 → Controller → Model 查询
    ↓
SQL WHERE 子句拼接 → 数据库执行 → 数据泄露
```

```markdown
## [严重度] 漏洞标题

### 基本信息
- **位置**：`src/path/file.ext:行号`
- **CWE**：CWE-XXX
- **CVSS**：X.X (如适用)

### 攻击者画像
[外部用户/已认证用户/内部服务]

### 输入向量
[具体可控输入：请求头/参数/URL/文件上传]

### 代码路径
```
[文件1:行号] 输入接收
[文件2:行号] 数据处理
[文件3:行号] 漏洞触发点 ←
```

### 影响评估
[具体可量化影响]

### 修复建议
```[语言]
// 修复后代码
```
```

### 无漏洞报告

```
审计完成——未发现中等或更高严重度的已确认漏洞。
```

## 审计检查清单

### 认证与访问控制
- [ ] 会话令牌是否使用加密安全随机数
- [ ] 密码是否使用 bcrypt/argon2 哈希
- [ ] 所有管理接口是否强制权限校验
- [ ] 敏感操作是否需要 MFA/二次确认

### 注入防护
- [ ] 数据库查询是否使用参数化查询
- [ ] 命令执行是否避免 shell 调用
- [ ] 文件路径是否校验规范化
- [ ] 模板渲染是否禁用动态执行

### 外部交互
- [ ] Webhook 回调是否校验签名
- [ ] 出站请求是否限制目标地址
- [ ] 第三方凭证是否从环境变量加载

### 敏感数据
- [ ] 日志是否排除敏感字段
- [ ] 密钥是否从 vault/env 加载
- [ ] 敏感数据是否在内存中及时清理

## 注意事项

1. **误报容忍**：宁可遗漏，不可错报
2. **上下文重要**：同一代码在不同场景严重度不同
3. **利用可行性**：必须能论证端到端利用路径
4. **修复优先级**：严重漏洞优先于代码风格建议

```

```

## 使用方式

当用户请求进行安全审计时，自动调用此 Skill。

**触发词**：
- "安全审计"
- "漏洞扫描"
- "安全检查"
- "security audit"
- "漏洞评估"

**审计执行流程**：

1. **确定被审计项目路径**
   - 从用户输入或当前工作目录确定项目路径

2. **创建报告目录**（如不存在）
   ```bash
   mkdir -p {项目路径}/docs/security_audit
   ```

3. **执行审计**
   - 按阶段1-3执行审计流程

4. **生成报告**
   - 使用报告模板填充内容
   - 按命名规则命名：`【YYYYMMDD】_SECURITY_AUDIT_REPORT_V1.md`
   - 保存到 `docs/security_audit/` 目录

5. **向用户返回审计结果摘要**
   - 列出发现漏洞数量和严重度分布
   - 提供报告完整路径
