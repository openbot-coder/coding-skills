# Vibe Coding Initialize

> Phase 0 → 初始化项目：创建目录结构、需求模板、状态文件

## 何时使用

- 首次在项目中引入 vibe-coding
- 需要为新变更创建工作区

## 执行流程

### Step 1：创建目录结构

```bash
mkdir -p docs/vibe-coding/changes
mkdir -p evidence
```

### Step 2：创建需求文档模板

在 `docs/vibe-coding/` 创建 `design.md`：

```markdown
# {项目名称} 设计文档

## 基本信息

| 字段 | 内容 |
|------|------|
| 项目名称 | {项目名称} |
| 版本 | 0.1.0 |
| 创建日期 | {日期} |
| 最后更新 | {日期} |

---

## 需求定义

### 背景
> 为什么需要这个功能？解决了什么问题？

{描述业务背景和用户痛点}

### 目标
> 用户希望实现什么？

1. {目标1}
2. {目标2}
3. {目标3}

### 范围
> 包含什么？不包含什么？

**包含**：
- {功能A}
- {功能B}

**不包含**：
- {功能C}（计划在 v2.0 实现）

### 成功标准
> 如何判断功能已完成？

| 标准 | 验收方式 | 优先级 |
|------|----------|--------|
| {标准1} | {验收方式} | P0 |
| {标准2} | {验收方式} | P1 |

### 用户故事

作为 {角色}，
我希望 {功能}，
以便 {收益}。

---

## 审批状态

> ⚠️ 人工审批点：需求文档必须经过人工审批后才能进入开发

| 阶段 | 状态 | 审批人 | 时间 | 备注 |
|------|------|--------|------|------|
| 需求定义 | ⬜ 待审批 | - | - | - |
| 设计审查 | ⬜ 待执行 | - | - | - |
| 最终验收 | ⬜ 待执行 | - | - | - |

---

## 阶段状态

| 阶段 | 状态 | 开始时间 | 完成时间 |
|------|------|----------|----------|
| 需求定义 | ⬜ 待执行 | - | - |
| 任务拆解 | ⬜ 待执行 | - | - |
| SDD 开发 | ⬜ 待执行 | - | - |
| 集成测试 | ⬜ 待执行 | - | - |
| 最终验收 | ⬜ 待执行 | - | - |

---

## 架构概览

### 模块划分
{简要描述主要模块及其职责}

- 语言：{语言版本}
- 测试框架：{测试框架}
- 构建工具：{构建工具}

---

## 变更历史

| 版本 | 日期 | 变更内容 | 作者 |
|------|------|----------|------|
| 0.1.0 | {日期} | 初始版本 | {作者} |
```


## 交付物清单

| 文件 | 位置 | 说明 |
|------|------|------|
| `design.md` | `docs/vibe-coding/` | 需求文档 + 审批状态 |
| `progress.md` | `docs/vibe-coding/` | 进度追踪 |
| `evidence/manifest.md` | `evidence/` | 证据总表 |

## 触发条件

执行 `python scripts/design.py --init --name <项目名> --lang <语言>` 后自动触发。

## 反模式

- ❌ 不创建目录结构就开始编码
- ❌ 跳过需求模板直接开始
- ❌ 需求定义不完整就审批
