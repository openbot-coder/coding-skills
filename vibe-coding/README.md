# Vibe Coding

> 人管两头，AI 跑中间。需求审批和最终验收由人掌控，中间开发过程由 AI 自驱动完成。

## 核心理念

| 阶段 | 执行者 | 说明 |
|------|--------|------|
| 需求定义 | 👤 人 | 用户提交需求，AI 自审后提交审批 |
| 任务拆解 | 🤖 AI | 自动拆解任务、生成优先级 |
| SDD 开发 | 🤖 AI | 规范驱动，100% 覆盖率 |
| 调试验证 | 🤖 AI | 失败 → 诊断 → 修复 → 重测 |
| 最终验收 | 👤 人 | 用户验收测试报告和变更 |
| 归档 | 🤖 AI | Git 提交、打标签、PR |

## 快速开始

### 1. 初始化项目

```bash
python scripts/design.py --init --name my-project --lang python
```

### 2. 用户填写需求

编辑 `docs/vibe-coding/design.md`：

```markdown
## 需求定义

### 背景
{描述业务背景}

### 目标
1. {目标1}
2. {目标2}

### 成功标准
| 标准 | 验收方式 | 优先级 |
|------|----------|--------|
| {标准} | {方式} | P0 |

## 审批状态
| 阶段 | 状态 | 审批人 | 时间 |
|------|------|--------|------|
| 需求定义 | ⏳ 待审批 | - | - |
```

### 3. AI 自审 + 提交审批

AI 自动检查需求完整性，输出自审报告，更新状态为 `⏳ 待审批`。

### 4. 用户审批

```markdown
| 需求定义 | ✅ 已批准 | 宝爷 | 2026-05-23 |
```

### 5. AI 自动开发

AI 按顺序执行：

```bash
# Phase 1: 任务拆解
# AI 自动执行 task-breakdown/，生成 progress.md

# Phase 2: SDD 开发
# AI 逐个完成任务，Git 自动提交

# Phase 3: 调试验证
# AI 自动测试、诊断、修复
```

### 6. 用户验收

```markdown
| 最终验收 | ⏳ 待验收 | - | - |
```

AI 输出测试报告和变更总结。用户审批：

```markdown
| 最终验收 | ✅ 已批准 | 宝爷 | 2026-05-23 |
```

## 审批状态机制

审批状态是 AI 执行的唯一依据。`design.md` 中：

```markdown
## 审批状态

| 阶段 | 状态 | 审批人 | 时间 |
|------|------|--------|------|
| 需求定义 | ✅ 已批准 | 宝爷 | 2026-05-23 |
| 设计审查 | ⏳ 待审批 | - | - |
| 最终验收 | ⬜ 待执行 | - | - |
```

AI 看到：
- `✅ 已批准` → 进入下一阶段
- `⏳ 待审批` → 停止并请求审批
- `⬜ 待执行` → 自动执行该阶段

## 关键原则

### 人管两头

1. **需求审批**：需求文档必须由人填写并审批
2. **最终验收**：测试报告和变更必须由人验收

### AI 跑中间

- 任务拆解、设计开发、测试验证全部由 AI 自驱动
- AI 自动更新 `progress.md` 和 `design.md` 中的阶段状态
- AI 自动提交 Git，记录每次变更

### SDD 规范

每个功能开发遵循：

```
写规范（Spec）→ 写实现（Implement）→ 写测试（Test）
```

不允许跳过或颠倒顺序。

### 100% 覆盖率

核心业务逻辑必须达到 100% 测试覆盖率。
